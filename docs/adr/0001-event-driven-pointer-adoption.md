# 서브모듈 변경에 따른 직접 버전 채택

세 서브모듈의 develop 변경을 계기로 검증한 버전을 gods-system/develop에 봇이 직접 커밋한다. PR 승인 단계 없이 자동으로 채택 버전을 갱신하기 위한 결정이다.

검증 범위는 후보 커밋이 해당 서브모듈의 develop에 속하는지 확인하고, 세 서브모듈을 각각 지정된 정확한 SHA로 체크아웃할 수 있는지 확인하는 것이다. 제품 통합 테스트와 실제 서비스 배포는 이 검증의 범위에 포함하지 않는다.

실행 계기는 서브모듈 변경으로 한정한다. 예약 실행과 별도의 수동 실행 진입점은 두지 않는다.

저장소 간 인증은 GitHub App을 사용한다. 실행 시점의 최신 develop SHA를 채택하며 중간 커밋마다 슈퍼 저장소 커밋을 만들지는 않는다. 슈퍼 저장소 쓰기는 직렬화한다.

검증 실패 시 기존 포인터를 유지하고 Actions 실행에 실패를 기록한다. 다음 서브모듈 변경 이벤트에서 다시 검증하며, 실패를 이유로 예약 재시도나 수동 실행 진입점을 추가하지 않는다. 다음 변경이 없다면 포인터는 그대로 유지된다.
